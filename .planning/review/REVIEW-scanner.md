# Read-Only Review: Portunity port-core Scanning / Data Layer

Scope: `port-core/src/scanner.{rs,tcp.rs,udp.rs,resolver.rs}`, `models*`, `filter.rs`,
`config*`, `store*`, `lib.rs`, `windows.rs`, `firewall.rs`, `history.rs`, `traffic.rs`.
Method: static reading only; no files modified, nothing executed. Findings verified
against ARCHITECTURE.md, REQUIREMENTS.md, STATE.md, and the phase PLAN/SUMMARY docs.

## Summary

- **The combined scan runs **three full sysinfo refreshes and one is not even on a blocking worker**.** `scan_tcp` and `scan_udp` each run `System::new_all()` + `refresh_all()` and resolve names inline (`tcp.rs:371,422-423`, `udp.rs:217`), then `scan_all` re-resolves every PID a *third* time via `ProcessResolver` (`scanner.rs:59-60`, `resolver.rs:67-68`) and *overwrites* the names those two refreshes just computed (`scanner.rs:63-68`) — two of three refreshes are pure waste, scaling linearly with process count and scan frequency (Phase 3 will ETW-trigger scans, SCAN-05).
- **The second resolve step runs sysinfo directly on the tokio worker thread** — `scanner.rs:59-60` — violating the project's own Pitfall #9 / ARCHITECTURE.md anti-pattern 3 ("all blocking Win32 calls wrapped in `spawn_blocking`") and STATE.md's "async-first API" decision; the post-pass is correctly wrapped in its own `spawn_blocking` (`scanner.rs:76-83`), making the inconsistency visibly avoidable.
- **Byte order, buffer retry, and the merged list are fundamentally correct** (verified: `ntohs` on the low 16 bits, `format_ipv4`'s `from_be→to_be_bytes` on LE, retry doubles from the OS-reported size), but the IPv4-mapped dedup keys on `(port, protocol)` **ignoring PID and state** — a v4 `TIME_WAIT`/`ESTABLISHED` row for a port suppresses a different process's brand-new mapped-v6 listener (`tcp.rs:394-400`, `udp.rs:242-247`).
- **The model drops data Phase 3 cannot live without**: no `local_address` (SCAN-01/02 require "local address:port"; FEATURES.md's `port_events` schema needs `local_addr`), no scan-time `start_time` (`handle.rs:39-40` says scan rows have none), and models lack `serde` derives for the EventBus/GUI boundary.
- **`firewall.rs`/`history.rs`/`traffic.rs` are trait-only stubs with zero implementations and zero consumers**; the store has no migration framework or shared-connection wrapper; tests cover pure helpers only — the actual scan/merge/resolve/store/config code paths are untested.

## Phase-3 seam notes (what ETW / history / traffic will need from this layer)

- **EventBus (CORE-03)** — `scan_all` is a free function returning `Vec<Connection>`; there is no events module. Add one choke point that publishes a typed `CoreEvent::PortsScanned` (ARCHITECTURE.md:376-402); models need `serde` first. The broadcaster is multi-producer, so TUI and GUI can both publish — fine.
- **History (HIST-01..04)** — `HistoryStore` is an unimplemented trait. Recording needs a pure, testable `diff(prev_scan, next_scan) -> Vec<PortChange>` so Occupied/Released/Changed can be classified without guessing semantics in Phase 3 — write that diff now with unit tests. It also needs a stable identity for "same process": scan rows carry no `start_time` (`handle.rs:39-40`), so PID reuse between scans is indistinguishable from a state change; the model must surface the creation FILETIME at scan time (a deliberate tradeoff vs D-16's "no per-PID OpenProcess" — decide it explicitly).
- **Traffic (TRAF-01..03)** — `Connection.bytes_sent/bytes_received` exist but are zeroed every scan; ETW delivers per-PID/per-port rates that must accumulate against a key stable across scans: `(pid, protocol, local_port, local_address)` — again requiring `local_address`. Add the field and an accumulator keyed on it now.
- **SCAN-05 ETW-triggered scans** — every event multiplies the per-scan costs above (3× sysinfo, settings I/O, filter clone, dedup). STATE.md:43 already decided ETW is a trigger only and `GetExtendedTcpTable` stays authoritative, so `scan_all` must be cheap — the CRITICAL items are prerequisites, not preferences.
- **Store** — WAL + `busy_timeout=5000` are already right (PITFALLS.md handles dual-frontend access); add `user_version` migrations, a shared connection wrapper with serialized writes, and the 100 ms write-batching ARCHITECTURE.md:510 calls for before ETW bursts create many tiny writes.

## Optimization shortlist (ordered by expected impact)

1. One sysinfo refresh per scan: delete inline resolution from `tcp.rs`/`udp.rs`; resolve once in `scan_all` with `refresh_processes`-only — removes ~2/3 of process-enumeration cost per scan.
2. Run the batch resolve inside `spawn_blocking` (fixes the async-worker stall; merge with the existing post-pass scope).
3. Cache `load_settings` with mtime invalidation; atomic save (temp + rename) to eliminate the whitelist-loss window.
4. `filter.rs`: precompute lowercase terms; filter without cloning the whole list.
5. Include PID (and state) in the mapped-dedup key; add a TIME_WAIT regression test.
6. Replace hand-rolled IPv6/IPv4 formatting with `std::net` types.
7. Add `local_address` (+ scope) and scan-time start time to `Connection` now.
8. Extract pure, CI-safe seam functions (row→Connection with an injectable formatter, dedup decision, retry sizing) so the hot path becomes testable off-Windows.

## Notes on the task's context claims

- "buffer retry 16KB→128KB" — partially inaccurate: the code doubles from the **OS-reported required size**, so allocations can exceed 128KB; the "max 128KB" note in STATE.md:51 does not match `tcp.rs:70-76`/`udp.rs:66-72`. Retry convergence is fine; only the documented cap is wrong.
- "resolver cache staleness (PID reuse → stale names)" — not currently a risk: `ProcessResolver` is recreated per scan (`scanner.rs:59`), so staleness is bounded to one scan. The risk appears only if the cache is hoisted into app state for performance in Phase 3 — which the dead `insert()` API invites. Pair any future cache with a start-time key.
- "Every scan runs in spawn_blocking" — **not true**: the `resolve_batch` step runs directly on the async worker (`scanner.rs:59-60`). This is the one place the stated contract is violated.
