# 功能调研

**领域：** Windows 端口管理工具
**调研日期：** 2026-07-26
**置信度：** MEDIUM（跨 6+ 个竞品交叉对比，无用户访谈）

## 功能全景

### 基本盘（用户期望）

用户认为理所当然的功能。缺少 = 产品不完整。从 `netstat` 到 `portio` 每个工具都有。

| 功能 | 期望原因 | 复杂度 | 备注 |
|------|----------|--------|------|
| **实时端口列表** — 显示所有活跃 TCP/UDP 端口及所属进程 | 端口管理器的全部意义。`netstat -ano` 是每个开发者已经在用的基线 | 低（IP Helper API） | 必须显示协议、本地地址:端口、远程地址:端口、状态、PID、进程名 |
| **端口→进程映射** — 显示哪个可执行文件占用了端口 | 用户需要立刻回答"端口 3000 上是什么？" | 低 | 必须显示完整路径；只有 `node.exe` 不够 |
| **搜索/过滤** — 按端口号、进程名、PID、协议、状态过滤 | TCPView **完全缺失过滤** — 这是其最高频用户投诉，导致大量用户转向 CurrPorts | 中 | 必须支持子串和精确匹配 |
| **进程终止** — 结束占用端口的进程 | "端口被占用"是打开端口工具的首要触发场景 | 低 | 操作前必须验证 PID 仍然有效（PID 重用风险） |
| **协议和状态显示** — TCP/UDP、LISTENING/ESTABLISHED/TIME_WAIT | 需要区分活跃监听和 TIME_WAIT 的过期连接 | 低 | 状态颜色编码是可视工具的基本盘 |
| **可排序列** — 点击表头排序 | 任何表格工具的 UX 基线 | 低 | 数值列（端口、PID）+ 字典序（进程名、状态） |
| **管理员提权** — 检测并在需要时请求管理员权限 | 终止系统进程需要管理员权限。自动检测 + UAC 提示是现代模式 | 中 | 必须自动检测，不能要求"始终以管理员运行" |
| **复制/导出数据** — 复制选中行或导出 | 用户需要分享发现（"端口 5432 被 PID 8840 占用，这是输出"） | 低 | 制表符分隔的剪贴板复制是最低要求 |
| **自动刷新** — 周期性刷新端口列表 | 端口不断变化。静态快照 5 秒后就没用了 | 低 | 可配置间隔。ETW 驱动推向"事件发生时"；2s 轮询是标准兜底 |

### 差异化功能（竞争优势）

让 Portunity 与众不同的功能。现有工具（TCPView、CurrPorts、Resource Monitor、portio、Porter）没有一个能组合超过 2-3 个。

| 功能 | 价值主张 | 复杂度 |
|------|----------|--------|
| **自动标注端口** — 识别常用开发端口并显示人类可读标签（5173→"Vite Dev Server"、5432→"PostgreSQL"） | 现有工具都没有。开发者记住端口号；新手不知道。标注弥合了这一差距 | 低（查表） |
| **自定义标签** — 用户可为端口命名（"我的生产数据库隧道"） | 端口列表变得个性化有意义。无竞品提供。用户记住自己的标签 | 低 |
| **分面组合搜索** — 跨端口、进程名、PID、协议、状态、标签、收藏同时搜索，AND/OR 逻辑 | CurrPorts 有过滤语法但无分面 UI。TCPView 零过滤 | 高 |
| **智能终止** — 优雅终止（WM_CLOSE → 等待 → TerminateProcess），可配置超时 | 几乎所有工具都强制终止。智能终止让服务器刷新缓冲、优雅关闭连接 | 中 |
| **即时终止 + 白名单保护** — 默认快速终止用户进程；白名单内系统进程需确认 | 速度+安全的平衡。约 30 个系统关键进程受保护；用户可在设置中自定义 | 中 |
| **端口占用变化历史** — 端口打开/关闭的时间线 | 无现有工具有持久端口历史。回答"那个开发服务器什么时候崩溃释放了端口 3000？" | 高 |
| **网络流量统计** — 每端口/每进程收发字节数 | ProcessTCPSummary 和 NetLimiter 提供此功能，但无端口管理器做。开发者想知道连接是真的在传输数据还是空闲 | 高 |
| **Windows 防火墙规则管理** — 在端口工具内创建/删除/启禁防火墙规则 | 替代流程是"找端口 → 打开防火墙高级设置 → 手动创建规则"。右键→"阻止此端口"是巨大的工作流改进 | 高 |
| **快捷阻止/放行** — 右键端口→"在防火墙中阻止"或"在防火墙中放行" | 无现有端口工具集成防火墙操作。将防火墙管理从独立管理任务变为端口发现的自然延伸 | 中 |
| **收藏/书签** — 保存常用监控端口 | 开发者总是检查相同的端口（3000、8080、5432） | 低 |
| **进程详情面板** — 可执行文件路径、启动时间、命令行参数、数字签名状态 | 完整进程上下文回答："这是我的实例还是别人的？""这是签名二进制还是恶意软件？""它用了什么命令行标志？" | 中 |
| **ETW 事件驱动刷新** — ETW 推送连接变化事件，2s 轮询兜底 | 其他工具要么轮询（空闲时烧 CPU）要么固定刷新率（错过快速变化）。ETW 仅在有变化时推送事件 | 高 |
| **双界面 — TUI + GUI 共享核心** | 无现有端口管理器同时提供终端 TUI 和桌面 GUI。这是结构性差异化而非单一功能 | 高 |

### 反功能（常见需求但有问题）

| 功能 | 为什么被要求 | 为什么有问题 | 替代方案 |
|------|--------------|--------------|----------|
| **主动 TCP 端口扫描**（nmap 式） | "我想看远程主机 Y 上端口 X 是否开放" | 这是安全/网络侦察工具，不是端口管理器。触发 IDS 告警，对非自有主机可能违法。端口扫描是根本不同的产品类别 | 保留 PortScanner trait 作为扩展点。v1 不做 |
| **实时网络吞吐量图表**（常驻前台带宽图） | "我想实时看流量尖峰" | 持续渲染的高 CPU/GPU 开销。增加视觉噪音分散核心端口列表注意力 | 提供流量统计（聚合字节数，几秒刷新一次）。若要图表，做可折叠面板 |
| **自动终止进程**（watch 模式，自动杀死任何占用被监视端口的进程） | "我不想手动杀进程，自动杀任何占我端口的东西" | 在共享机器上极其危险。同事启动服务器 — 自动被杀。合法系统服务绑定端口 — 自动被杀 | 提供通知式的 Watch（toast、托盘提醒），让用户决定是否 kill |
| **原始数据包捕获/深度包检测**（Wireshark 式） | "我想看连接中发送的数据" | 需要内核级抓包（WinPcap/Npcap 驱动安装），添加驱动签名复杂性 | 显示连接元数据。数据包检查用 Wireshark |
| **"全部杀死"按钮** | "我想一次性释放所有端口" | 会终止系统关键进程（svchost.exe 托管数十个 Windows 服务），有蓝屏风险 | 不提供。批量操作需显式多选，白名单始终生效 |
| **内建 HTTP 服务器远程访问** | "我想从手机查看端口" | 给本地系统工具添加完整 Web 服务器（认证、TLS、CORS）带来远程攻击面 | 保持本地。TUI 原生支持 SSH |
| **服务管理**（启动/停止 Windows 服务） | "如果看到服务占用端口，想重启它" | 服务有复杂依赖链，重启可能级联。端口管理器不是服务管理器 | 显示关联服务名作为信息参考 |

## 竞品分析关键洞察

1. **过滤是市场最大缺口。** TCPView 完全缺失过滤功能是其最高频投诉。Portunity 的分面搜索直接打这个痛点。
2. **没有工具组合端口管理与防火墙管理。** "找端口→阻止它"的工作流当前需要跨工具。Portunity 可以端到端覆盖。
3. **历史和标注是未满足的需求。** 没有工具帮助用户记住"昨天端口 3000 上是什么"或"这 5 个 node.exe 哪个是我的 API 服务器"。
4. **流量统计在独立的工具类别中。** ProcessTCPSummary 和 NetLimiter 有流量统计但不显示端口上下文。Portunity 可以在端口列表旁显示字节数。
5. **终止体验普遍糟糕。** 大多数工具强制终止。部分缺乏确认。没有工具提供优雅终止升级。智能终止+白名单是真正的 UX 差异化。
