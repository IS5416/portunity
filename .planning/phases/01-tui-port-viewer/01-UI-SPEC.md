# Phase 1 — UI Design Contract (TUI)

> Visual and interaction contract for the terminal-based port viewer. Generated by gsd-ui-researcher, adapted for TUI context (Ratatui + crossterm). Verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Framework | Ratatui 0.30.2 |
| Backend | crossterm 0.29.0 |
| Widget library | eddacraft-tui 0.4.0 (DataTable for port list), ratatui-widgets 0.7.10 |
| Rendering | Double-buffered, synchronized output (`CSI ? 2026 h`/`l`), batched writes |

## Layout & Spacing

Terminal rendering uses a fixed character-cell grid. Layout constraints are expressed in rows, columns, and percentage ratios, not pixels. Ratatui `Constraint` enum defines the layout engine.

### Panel Layout (every tab)

```
┌─ Tab Bar ──────────────────────────────────────────┐   Row 0: 1 row
│ [1] Overview  [2] Ports  [3] History  [4] Traffic… │
┡━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┩
│                                                     │   Rows 1..(N-3):
│               Content Area                          │   Remaining space
│       (per-tab widget, see Widget Inventory)        │
│                                                     │
├─ Status Bar ────────────────────────────────────────┤   Row (N-2): 1 row
│ Live · 847 ports · Admin ✓ · 12:34:56              │
├─ Footer ───────────────────────────────────────────┤   Row (N-1): 1 row
│ [1-5]Tabs [Tab]Focus [/]Search [f]Filter [r]Refresh│
└─────────────────────────────────────────────────────┘
```

### Layout Constraints

| Region | Constraint | Behavior on Resize |
|--------|-----------|-------------------|
| Tab bar | `Length(1)` | Fixed 1 row |
| Content area | `Min(20)` proportional fill | Expands/contracts with terminal |
| Status bar | `Length(1)` | Fixed 1 row |
| Footer | `Length(1)` | Fixed 1 row |
| Help overlay | Centered popup, 60 cols x 20 rows, `Clear` background | Fixed size, centered |
| Search bar | `Length(3)` popup at top of content area | Full width of content area |
| Filter panel | `Length(5)` inline below search | Fixed 5 rows when visible |

### Minimum Size Gate

| Condition | Behavior |
|-----------|----------|
| Terminal < 80x24 | Render centered message: "Terminal too small. Minimum: 80x24. Current: {w}x{h}" |
| Terminal >= 80x24 | Full layout renders proportionally |

### Column Layout (Port Table)

When content area width >= 80 cols, the port table renders all columns. Below 80 cols, columns collapse by priority:

| Priority | Column | Min Width | Collapse Below |
|----------|--------|-----------|----------------|
| 1 (keep) | State indicator | 1 | Never collapsed |
| 2 (keep) | Port | 8 | Never collapsed |
| 3 (keep) | Protocol | 4 | Never collapsed |
| 4 | Process Name | 12 | 60 cols |
| 5 | PID | 6 | 50 cols |
| 6 | Local Address | 18 | 40 cols |
| 7 | Remote Address | 18 | 40 cols |

**Source:** TUI-07 (minimum 80x24, graceful degradation on resize) from REQUIREMENTS.md; column priority from SCAN-01, SCAN-02.

## Typography

Terminal emulators use a single monospace font determined by the user's terminal settings. The application has no control over font family, size, or line height. **All text is monospace. All cells are equal width.**

### Text Modifiers (the only typographic levers available)

| Modifier | SGR Code | Usage |
|----------|----------|-------|
| **Bold** | SGR 1 | Column headers, tab labels (active), section titles, status bar labels |
| **Dim** | SGR 2 | Metadata (timestamps, PID, process ID), secondary info, inactive tab labels |
| _Italic_ | SGR 3 | Not used in Phase 1 (terminal support inconsistent). Reserved for Phase 6 labels. |
| Underline | SGR 4 | Interactive/hotkey characters in footer and help overlay |
| Reverse | SGR 7 | Selected row highlight (primary selection indicator) |
| Strikethrough | SGR 9 | Not used in Phase 1. Reserved for Phase 2 terminated processes. |

### Visual Hierarchy

| Role | Modifier | Color Slot | Example |
|------|----------|------------|---------|
| Tab label (active) | Bold + Reverse | `accent.primary` bg | **[2] Ports** |
| Tab label (inactive) | Dim | `fg.muted` | [1] Overview |
| Column header | Bold | `fg.emphasis` | **State  Port  PID  Process** |
| Selected row | Reverse | `bg.selection` | entire row inverted |
| Port number | None | `fg.default` | 8080 |
| Process name | None | `fg.default` | nginx.exe |
| Timestamp | Dim | `fg.muted` | 12:34:56 |
| Status bar label | Bold | `fg.muted` | **Live** |
| Status bar value | None | `fg.default` | 847 ports |
| Filter input prompt | Bold | `accent.primary` | **/>_** |
| Help key label | Bold + Underline | `accent.primary` | **q** |

**Source:** TUI-07 (monospace constraint inherent to terminals); hierarchy patterns from tui-design skill.

## Color

### Theme: One Dark (Phase 1 default)

Phase 1 uses a single hardcoded dark theme based on One Dark. Theme system (6 presets, TOML files, `t` key toggle) is Phase 6. No user-facing theme selection exists yet; all color values are compile-time constants.

### Semantic Color Slots

Colors are defined by semantic role, not hex value. Implementation maps slots to terminal colors (256-color palette with 16 ANSI fallback). Detection: `$COLORTERM` → true color preferred; `$NO_COLOR` → monochrome mode (all color disabled, layout + reverse-only).

| Slot | 256-Color | True Color (hex) | ANSI Fallback | Purpose |
|------|-----------|-------------------|---------------|---------|
| `fg.default` | 252 | `#abb2bf` | White | Body text, port numbers, process names |
| `fg.muted` | 241 | `#5c6370` | Bright Black | Metadata, timestamps, inactive tabs, TIME_WAIT state |
| `fg.emphasis` | 255 | `#e5e5e5` | Bright White | Column headers, section titles |
| `bg.base` | 234 | `#1a1b26` | Black | Main background |
| `bg.surface` | 235 | `#24283b` | Black | Panel backgrounds, table rows (odd) |
| `bg.overlay` | 236 | `#2c3043` | Black | Search bar, filter panel, help overlay background |
| `bg.selection` | 237 | `#364a82` | Blue | Selected row background (paired with reverse) |
| `accent.primary` | 39 | `#61afef` | Cyan | Focus indicators, search prompt, interactive hints, active tab border |
| `accent.secondary` | 170 | `#c678dd` | Magenta | Not used in Phase 1. Reserved for Phase 2 kill action highlights. |
| `status.success` | 42 | `#98c379` | Green | LISTENING state, success messages, admin-OK indicator |
| `status.warning` | 214 | `#e5c07b` | Yellow | CLOSE_WAIT state, admin-needed warning, filter active indicator |
| `status.error` | 203 | `#e06c75` | Red | Error messages, SYN_SENT state, access-denied indicator |
| `status.info` | 38 | `#56b6c2` | Blue | ESTABLISHED state, info messages, refresh indicator |

### Connection State Color Map

Per SCAN-03 from REQUIREMENTS.md:

| State | Color Slot | Visual | Reason |
|-------|-----------|--------|--------|
| LISTENING | `status.success` | Green circle ● | Server ready — positive/stable |
| ESTABLISHED | `status.info` | Blue circle ● | Active connection — neutral/informational |
| TIME_WAIT | `fg.muted` | Gray circle ○ | Transient cleanup — low importance |
| CLOSE_WAIT | `status.warning` | Yellow circle ◉ | Waiting on local close — attention needed |
| SYN_SENT | `status.error` | Red circle ● | Outbound attempt — rare, may indicate issues |
| FIN_WAIT* | `fg.muted` | Gray circle ○ | Shutdown sequence — transient |
| UDP (no state) | `fg.muted` | Gray dash — | Stateless protocol — informational only |

### Dominant/Surface Breakdown (60/30/10 Rule)

| Role | Color Slot | Coverage | Elements |
|------|-----------|----------|----------|
| Dominant (60%) | `bg.base` | Background | Main viewport, empty tab panes |
| Secondary (30%) | `bg.surface`, `bg.overlay` | Panels, popups | Table row backgrounds, search bar, filter panel, help overlay |
| Accent (10%) | `accent.primary` | Interactive focus | Active tab indicator, search prompt cursor, selected row border, footer hotkey hints |

**Accent reserved for:** active tab highlighting, search/filter input prompt, focused element border, footer hotkey underlines, and the row selection indicator. No other elements use accent color. Never applied to static content or body text.

### Background Layering (Depth)

```
bg.base (darkest) → bg.surface → bg.overlay (lightest)
```

Each step ~5-8% lighter. Creates perceived depth without heavy borders. The tab bar and status bar use `bg.surface` to distinguish from main `bg.base` content area.

**Source:** SCAN-03 (connection state colors) from REQUIREMENTS.md; semantic slots and layering from tui-design skill; One Dark palette adapted from Phase 6 theme list (TUI-05) — this is the first preset, converted to semantic slots.

## Copywriting Contract

### Primary CTA
| Element | Copy |
|---------|------|
| Initial launch CTA | No explicit CTA — app auto-scans on launch. First-run empty state shows "Scanning ports..." spinner. |

### Empty States

| Element | Heading | Body |
|---------|---------|------|
| No ports found | "No active ports" | "No TCP or UDP ports are currently in use. This is unusual — check if network services are running." |
| Search returns nothing | "No ports match '{query}'" | "Try adjusting your search terms or press Esc to clear." |
| Filter has zero matches | "No matching ports" | "No ports match the current filters. Try broadening your criteria or press Esc to clear all filters." |
| Future tab (History/Traffic/Firewall) | "Coming later" | "This tab will be available in a future phase. Press 1 or 2 to view active tabs." |

### Error States

| Element | Problem Description | Next Step |
|---------|--------------------|-----------|
| Port scan failed | "Scan failed: {error_details}" | "Check that you have sufficient permissions. Press r to retry." |
| Admin access denied | "Limited detail: admin rights needed" | "Some process details are hidden. Run as administrator for full information. Press a to elevate." |
| Terminal too small | "Terminal too small" | "Minimum size: 80 columns x 24 rows. Current: {w}x{h}. Resize your terminal window to continue." |
| SQLite init failed | "Database error: could not initialize storage" | "Check disk space and write permissions in the application data directory. The app will continue with in-memory mode." |

### Destructive Actions

Phase 1 has NO destructive actions. Process killing is Phase 2. Admin elevation is the only elevated-privilege action:

| Action | Confirmation Approach |
|--------|----------------------|
| Admin elevation (UAC) | Status bar shows "Admin needed for full process details". User presses `a` to trigger UAC. Windows handles the elevation prompt natively. No in-app confirmation dialog needed — the OS prompt is the confirmation. |

### Status Bar Messages

| State | Message Pattern |
|-------|----------------|
| Idle (live) | `Live · {N} ports · Admin {✓/needed} · {HH:MM:SS}` |
| Scanning | `Scanning… · {N} found so far · Admin {✓/needed} · {HH:MM:SS}` |
| Filter active | `Filtered: {M} of {N} ports · "{filter description}" · Admin {✓/needed}` |
| Search active | `Search: "{query}" · {M} results` |
| Error | `⚠ {error message} · Press r to retry` |
| Elevated (post-UAC) | `Live · {N} ports · Admin ✓ · {HH:MM:SS} · Full process details available` |

### Footer (Context-Sensitive)

Default (no modifier active):
```
[1-5]Tabs [Tab]Focus [/]Search [f]Filter [r]Refresh [a]Elevate [q]Quit [?]Help
```

Search mode:
```
[Esc]Cancel [Enter]Confirm  —  fuzzy search across all fields
```

Filter mode:
```
[Esc]Cancel [Tab]Next field [Enter]Apply  —  filter by port/PID/process/state/protocol
```

**Source:** TUI-02 (keyboard shortcuts) from REQUIREMENTS.md; footer format from tui-design skill. Specific copy drafted per Phase 1 scope.

## Keyboard Contract

### Keybinding Layers

Per tui-design skill's four-layer keyboard model:

**L0: Universal** (always in footer)
| Key | Action |
|-----|--------|
| `1` `2` `3` `4` `5` | Switch to tab |
| `Tab` | Focus next panel/interactive element |
| `Shift+Tab` | Focus previous panel/interactive element |
| `Enter` | Select / confirm / apply |
| `Esc` | Cancel / dismiss / go back |
| `q` | Quit application |
| `↑` `↓` | Navigate rows (port list) |
| `←` `→` | Navigate within filter/search fields |

**L1: Vim-style** (always in footer)
| Key | Action |
|-----|--------|
| `j` / `k` | Move down / up in port list |
| `h` / `l` | Left / right (tab bar, or column collapse in future) |
| `/` | Open search bar |
| `?` | Open help overlay |
| `g` / `G` | Jump to top / bottom of list |

**L2: Actions** (shown in footer and help)
| Key | Action |
|-----|--------|
| `r` | Manual refresh (full re-scan) |
| `f` | Open filter panel |
| `a` | Request admin elevation (UAC) |
| `s` | Toggle sort column / cycle sort order |
| `Space` | Not used in Phase 1. Reserved for selection toggle (Phase 2). |

**L3: Power** (shown in help overlay only)
| Key | Action |
|-----|--------|
| `Ctrl+r` | Force full re-scan (bypass cache) |
| `Ctrl+f` | Toggle filter panel visibility |
| `Ctrl+l` | Clear all filters and search |

**Never bound (reserved by terminal):** `Ctrl+C` (interrupt), `Ctrl+Z` (suspend), `Ctrl+\` (quit signal), `Ctrl+S`/`Ctrl+Q` (flow control).

### Focus Management

| State | Visual Indicator | Active Keys |
|-------|-----------------|-------------|
| Tab bar focused | Active tab: Bold + `bg.surface` highlight. Inactive: Dim. | `1-5`, `←` `→`, `h` `l` |
| Overview tab focused | Stat tiles: bold numbers as primary visual anchor. Mini table: first row auto-focused on tab entry. Admin card: `a` key hint highlighted. Focus cycles: stat tiles → mini table → admin card. Focused panel gets `bg.surface` highlight. | `Tab` cycle panels, `↑` `↓` within mini table |
| Port list focused | One row: Reverse video highlight. Column header sort indicator: `▲`/`▼` beside sorted column. | `↑` `↓`, `j` `k`, `g` `G`, `Enter` (future drill-down) |
| Search bar focused | Cursor blinking in input field. Search prompt: `/>_`. | Text input, `Esc` cancel, `Enter` confirm |
| Filter panel focused | Focused field: `bg.overlay` + cursor. Other fields: `bg.surface`. | `Tab` cycle fields, `Enter` apply, `Esc` cancel |
| Help overlay (modal) | Dimmed background + centered popup. All background interaction blocked. | `↑` `↓` scroll, `Esc` or `?` dismiss |

### Sort Interaction

| Action | Visual |
|--------|--------|
| Press `s` once | Sort by current column, ascending. Column header shows `▲`. |
| Press `s` again | Same column, descending. Column header shows `▼`. |
| Press `←`/`→` then `s` | Move sort column, then sort. |
| Repeat sort on same column | Cycles: none → ascending → descending → none. |

**Source:** TUI-02 (keyboard navigation) from REQUIREMENTS.md; SCAN-04 (sort by any column); keyboard layers from tui-design skill.

## UI Considerations

> Populated from requirements analysis. Covers UI state coverage: empty, loading, error, populated, overflow, and edge cases.

Applicable state considerations resolved: 8 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Port table (no ports) | ✅ covered | "No active ports" empty state with body copy and suggestion. Spinner shown during scan, then transitions to empty if scan returns zero results. |
| empty | Search results | ✅ covered | "No ports match '{query}'" heading with Esc-to-clear hint in body. |
| empty | Filter results | ✅ covered | "No matching ports" copy with criteria-broadening hint. |
| loading | Initial scan | ✅ covered | Spinner widget with "Scanning ports..." status bar message. Port table populates incrementally as results arrive. |
| loading | Manual refresh | ✅ covered | Spinner replaces status bar timestamp. Existing table data remains visible (no blanking). "Scanning..." status. |
| error | Scan failure | ✅ covered | Error message in status bar with red `status.error` color. "Press r to retry" shown in footer. Previous data remains visible if available. |
| error | Admin access denied | ✅ covered | Status bar shows "Admin needed." Process details for system processes show "—" with dim modifier. `[a]Elevate` appears in footer. |
| overflow | Port table (1000+ rows) | ✅ covered | VirtualTable with virtual scrolling. Scrollbar indicator. `g`/`G` for jump navigation. |
| overflow | Long process name | ✅ covered | Truncate with `…` at column boundary. Full name visible on selection in future detail panel (Phase 2). |
| zero-one-many | Selected rows | ✅ covered | Zero: no selection highlight, footer shows default actions. One: row highlighted with reverse video, sort operates on table. Many: multi-select not supported in Phase 1 (reserved for Phase 2 batch kill). |
| long-text | Process path in status | 🧪 backstop | Long executable paths in future detail view (Phase 2). For Phase 1, process names are truncated in table at column width. |
| resize | Terminal resize < 80x24 | 🧪 backstop | "Terminal too small" gate renders. Proportional layout handling verified by integration test. Backstop: manual resize test at boundary. |
