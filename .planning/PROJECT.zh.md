# Portunity（Port + Opportunity）

## 这是什么

一款高性能 Windows 端口管理工具，支持分类检索、进程终止、流量监控和防火墙规则管理。双前端架构 —— Tauri 桌面 GUI 和 Ratatui 终端 TUI —— 共享 Rust 核心库。面向调试端口冲突的开发者、管理服务的运维人员、调查连接的安全审计者。

## 核心价值

瞬间找到、分类并操作任何活跃端口及其所属进程 —— 从发现到执行，零摩擦。

## 背景

- **开发者痛点：** 端口 3000/8080/5432 被占用，翻 netstat 找 PID，复制，手动 kill。每天重复。
- **无现成方案：** Windows 缺少专用端口管理工具。目前流程是 netstat + taskkill；资源监视器隐藏太深且只读。
- **Rust 生态匹配：** Tauri v2（桌面 GUI）、Ratatui（终端 TUI），都是 Rust 原生。共享核心 crate 避免逻辑重复。
- **Windows API 可用：** IP Helper API（`GetExtendedTcpTable`、`GetExtendedUdpTable`）、ETW 连接变化事件、Windows Filtering Platform 防火墙规则、`TerminateProcess` 进程终止。

## 约束

- **技术栈：** Rust（edition 2024），Tauri v2 + Svelte（GUI），Ratatui（TUI）
- **平台：** Windows 10/11 为主；Linux、macOS 仅预留扩展点
- **性能：** 端口扫描和刷新不能阻塞 UI；异步运行时（tokio）
- **存储：** SQLite 存历史、收藏、标签、设置
- **安全：** 系统关键进程不可不经确认直接终止；白名单可扩展

## 关键决策

| 决策 | 理由 | 结论 |
|------|------|------|
| 共享核心 crate（`port-core`） | 端口扫描、进程管理、过滤逻辑的单一真相源，双前端共用 | — 待验证 |
| Tauri v2，不用 v1 | 最新稳定版，IPC 性能更好，插件系统更强，v1 已进入维护模式 | — 待验证 |
| GUI 用 Svelte，不用 React/Vue | 编译输出无虚拟 DOM 运行时，打包体积最小，Tauri 社区推荐搭配 | — 待验证 |
| TUI 用 Tab 式 Widget Dashboard | 5 个独立功能域（概览、端口、历史、流量、防火墙），Tab 给每个功能域完整画布 | — 待验证 |
| SQLite，不用 JSON/sled | 最通用，Tauri 官方插件，rusqlite 生态成熟。JSON 历史数据多了性能差，sled 太冷门 | — 待验证 |
| ETW + 轮询兜底 | 事件驱动理想（不烧 CPU），2 秒轮询兜底捕获 ETW 可能遗漏的边界情况 | — 待验证 |
| 智能 kill（优雅 → 强制） | 优雅终止让服务器有机会清理关闭；强制杀作最后手段，最佳用户体验 | — 待验证 |
| 即时 kill + 白名单确认 | 大部分 kill 是故意的（开发者停自己的服务），白名单防止误杀系统进程 | — 待验证 |
| 仅系统 API 做端口扫描 | `GetExtendedTcpTable`/`GetExtendedUdpTable` 覆盖 100% 本地端口管理场景。TCP connect 扫描是另一个工具的活（nmap）。已预留扩展点 | — 待验证 |
| 自动检测管理员权限 + UAC 提权 | 杀某些进程需要管理员权限；自动检测并提示比"始终以管理员运行"或"静默失败"更好 | — 待验证 |
| 所有 v1+v2+v3 功能一步到位 | 用户要全功能工具，不要渐进式 MVP | — 待验证 |
| 英文 artifacts 供 Agent 使用 | Agent 处理英文更可靠。中文 PROJECT.zh.md 供人阅读 | — 待验证 |
